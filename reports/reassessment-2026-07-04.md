# Reassessment — 2026-07-04

**Summary:** Two feature cycles landed since 07-03 — richer default-expanded trip stops (map, full essentials/toolkit, booking card) and a site-wide re-theme defaulting to dark mode — and both introduce real regressions: reordering a trip's stops silently collapses/expands the *wrong* destination (position-keyed UI state, not identity-keyed), and `npx vitest run` now fails on `origin/main` because the richer stop detail duplicates safety-advisory text that an existing regression test asserted was unique. The dark-mode re-theme itself is solid (a broad, well-designed CSS remap layer) with only one small unmapped-class seam. The 3 accessibility gaps flagged 07-03 in `StopDetail`/`StopsSection` are still unfixed.

Assessed against `origin/main@1827df1` (7 commits ahead of the `d66e4de` baseline the 07-03 report reviewed), merged into the `reassessment-reports` branch for reading (never merged onward).

## Confirmed bugs

### 1. (New, medium impact) Manually-collapsed stop state is keyed by array index, not stop identity — reordering (or adding/removing) a stop silently collapses/expands the wrong destination
`src/components/StopsSection.tsx:31, 91, 106-113` — `collapsedIdx` is a `Set<number>` of positions in the `resolved` array. The move-up/move-down/add/remove handlers (`:173-220`) mutate `trip.stops`' order in place but never touch `collapsedIdx`, so a collapsed *position* silently reattaches to whatever stop now occupies it.

Reproduced live (seeded a 3-stop trip: Kyoto, Tokyo, Hokkaido):
1. All three stops render expanded by default (new default-open behavior).
2. Manually collapse "Hokkaido (Sapporo)" (index 2) → `aria-expanded="false"` on Hokkaido, as expected.
3. Click "Move up" on Hokkaido, swapping it into index 1.
4. Result: **"Tokyo & around"** (now at index 2, never touched by the user) is collapsed, while **"Hokkaido (Sapporo)"** (the one the user actually collapsed) is expanded again.

This is the same "state keyed by position instead of entity id" class CLAUDE.md's storage-scoping rule targets, just in in-memory component state rather than `localStorage`. Under the old (07-03 and earlier) `openIdx: number | null` single-selection model this was low-impact (at most one stop was ever open, and reopening was a simple re-click); the new "everything open, remember what you collapsed" model makes it a real, easily-triggered correctness bug for any multi-stop trip whose stops get reordered or edited after the user has tidied a few away. Not persisted (resets on reload), so no data loss — but the displayed content is simply wrong until the user notices and refixes it.

### 2. (New, CI-breaking) `npx vitest run` fails on `origin/main` — the new `TravelEssentials` block duplicates text an existing regression test asserted was unique
`test/stop-detail.test.tsx:57` — `expect(screen.getByText(/Very safe/)).toBeTruthy()` now throws `Found multiple elements with the text: /Very safe/`. The compact `SafetyNote` line ("🟢 Safety: Very safe.") introduced for the 07-02 cycle and the new `TravelEssentials` health `<dd>` ("Very safe; summer heat & humidity", `TravelEssentials.tsx`) both render the advisory text inside the same expanded `StopDetail`, so a query that used to match one element now matches two. **1 of 83 tests fails; `git log` shows this has been broken since the `richer-trip-stops` merge landed and was never caught** — this is exactly the "every fixed bug leaves a regression test" norm from CLAUDE.md working correctly to catch a *new* bug, except nobody looked at the result before merging. Fix is narrow (scope the query to a `within()` of the specific section, or make one of the two renderings' text distinct) but the test suite is currently red on `main`.

## Improvement opportunities

- **Fix the reorder/collapse-state bug (#1 above)** by keying `collapsedIdx` off `region.id` instead of array index — a `Set<string>` swap, same shape as the fix already applied elsewhere in this codebase for the analogous `TripView` `key={id}` fix from 07-03.
- **Fix the failing test (#2 above)** before it normalizes into "the suite is just red" — scope `test/stop-detail.test.tsx:57`'s query or de-duplicate the rendered safety text.
- **Still open, 2 cycles running:** the three `StopDetail`/`StopsSection` a11y gaps from 07-03 (`role="status"`, `role="alert"`, `aria-controls`/`id`) — unchanged, still worth a small pass.
- **Small dark-mode remap gap:** `bg-slate-100` (used ~37 places — skeleton loaders, progress-bar tracks, the stop-number badge circle) is not in the `.dark` remap list in `globals.css` (unlike `bg-slate-50` and `bg-white`, which are). Visually confirmed low severity — e.g. the numbered stop badge (`StopsSection.tsx:117`) still reads legibly since its paired text color's remapped value has enough contrast against the un-remapped light-gray circle — but it's a visual seam (a light-gray dot in an otherwise dark UI) worth folding into the remap list for consistency, especially since skeleton loaders using it flash on every async-loading state.
- **Performance/workflow note (not a bug):** stops now expand by default, so a trip page for an N-stop trip fires N parallel `/api/region-detail` fetches plus N `ClimateChart`/`WeatherNow`/`TripadvisorRating`/`RegionMap` mounts on load, instead of the previous lazy one-at-a-time fetch. Reasonable for short trips; worth watching for longer itineraries (6+ stops) where this could visibly increase load time and third-party API call volume (weather/Tripadvisor) per page view.
- The `mergeTrips` tombstone gap flagged 07-02/07-03 (`src/lib/supabase/trips.ts:138-162`) is still open; untouched this cycle.
